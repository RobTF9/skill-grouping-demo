# Release notes

Group the changes into Added, Changed, Fixed and Removed. Lead with what users see.

## Steps

1. Collect the merged pull requests since the last release.
2. Drop each change that users cannot see, such as a refactor or a test.
3. Put each change in one group, as [the categories](references/categories.md) say.
4. Write one line for each change, as [the style notes](references/style.md) say.
5. Put the most important change of each group first.
6. Add the release number and the date at the top.

## Past releases

The full history is in [the archive](references/changelog-archive.md). Match its format.
